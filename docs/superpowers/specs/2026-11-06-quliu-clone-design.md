## 13. 垃圾桶交互闭环需求（T7.3 · 2026-11-06 用户提出，状态图已确认中）

状态：浏览/首页 →(上滑删除)→ 垃圾桶有货 →(自动弹出)→ 垃圾桶确认页 ⇄(确认/取消)→ 系统删除确认 →(成功)→ 已删除；确认页 →(放弃清空)→ 浏览/首页。

R1 **常驻入口**：首页右上垃圾桶图标按钮，N>0 显示红色角标；N=0 点击提示"垃圾桶是空的"。
R2 **回首页自动弹**：任何路径回到照片首页（返回按钮/完成页返回首页/tab 切回）且队列>0 → 自动打开垃圾桶确认页（取代现有 Alert 弹窗）。
R3 **组结束自动弹**：已完成（T7.2）。
R4 **X 关闭**：确认页点 X → 保留待处理项返回来源页。
R5 **放弃**：清空队列，返回首页。
R6 **确认删除**：系统弹窗；成功→写删除记录+清 media 行+返回；取消→停留确认页并提示。
R7 **↩ 撤回**：浏览页撤回最近一次删除（移出队列）。
边界：R2 触发范围=进入照片首页；与 R3 不叠加（done 弹过、X 关闭后回首页会再弹一次——按用户要求"回首页就弹"执行）。

实现差量：R1 新增首页按钮（现仅红胶囊）；R2 将 goHome 的 Alert 改为直接 push /pending；其余已满足。

## 1. 意图与理由
以 iPhone app《去留 - 照片整理与随机回顾》(v1.61) 为蓝本，经 REA 逆向调研（见 `功能清单.md`），用 Expo/React Native 重新实现一个**功能等价、完全本地、无商业化**的照片回顾清理 app，并安装到用户已连接的 iPhone（iOS 27，设备名 augustone）上实际跑通核心流程。

动机：用户想要同款体验但去除会员/额度/云同步限制；同时作为可持续开发的自有项目。

## 2. 目标
- G1 核心循环完整可用：随机抽未看照片成组 → 上滑删（入回收站）/下滑收藏/左右切换/双击收藏/捏合回到那天 → 回收站确认 → 系统真删除 → 统计可见节省空间。
- G2 全部分类可浏览：照片/截屏/自拍/实况/动图/长图/视频；每组数量可调。
- G3 回到那天、重置浏览记录（分范围）、照片信息（EXIF+地图）、使用统计、设置（可选项）全部可用。
- G4 视觉近似：深色照片取样渐变背景、拍立得式卡片堆叠、胶囊 tab、毛玻璃元素、触感反馈。
- G5 交付：可运行源码 + iPhone 实机跑通（Expo Go）+ 构建/部署说明。

## 3. 非目标（用户明确排除）
每日额度、会员/订阅/RevenueCat/paywall、CloudKit 同步、桌面小组件、每日提醒、演示模式、Debug 实验室、分享运营活动、像素级复刻。
**合规红线**：不复制原 app 任何代码、图片、字体、Lottie 素材；仅参考功能与交互设计。

## 4. 反目标（做出来也不算成功）
- 只能看不能删（核心循环断裂）→ 删除必须真实作用于系统相册。
- 把原 app 的"限制感"带进来（额度、试用、锁）。
- 用 Web 方案糊弄（无法访问系统相册）。

## 5. 约束
- 本机无 Xcode、磁盘仅 20GB → 开发/调试/验收全部走 **Expo Go**（USB/Metro），不依赖本地 iOS 构建。
- 目标设备 iOS 27；Expo Go 内可用能力为上限：实况照片仅静态展示、HDR 尽力而为、灵动岛动效降级为顶部飞卡+触感。
- 独立安装包（脱离 Expo Go）是后续升级路径：装 Xcode 后 `expo prebuild` 或 EAS 云构建，不在本期验收范围。
- 隐私：照片数据不出设备；浏览/删除记录仅存本机 SQLite。

## 6. 备选方案（已决）
| 方案 | 取舍 | 结论 |
|---|---|---|
| A 原生 SwiftUI | 保真最高、独立 app；但需 ~40GB 磁盘装 Xcode | 未选（磁盘硬约束） |
| **B Expo/RN** | 零大安装、Expo Go 实机即跑、环节复用成熟；实况/HDR/岛动效降级 | **已选（用户确认）** |
| C Web/PWA | iOS 无法删系统相册照片，核心循环不成立 | 排除 |

## 7. 技术决策（我定的，均可被用户否决；已经 builder 评审修订）
- **栈**：Expo SDK 54/55 + TypeScript + expo-router；`expo-media-library`（读取/删除/收藏——官方 API：`deleteAssetsAsync`/`favoriteAssetsAsync`，评审确认 Expo Go 内真实可用）；`expo-image`（缩略图池、性能）；`expo-video`（视频页）；`react-native-reanimated` + `react-native-gesture-handler`（卡组手势与动画）；`expo-haptics`；`expo-sqlite`（数据层）；`react-native-maps` 1.20+（Apple Maps 提供器——**已核验官方文档"Included in Expo Go"**；注意新库 expo-maps 不在 Expo Go，不用）。
- **分类判定（评审问题1的解）**：不依赖 mediaSubtypes（API 不暴露），改用**系统智能相册成员**：`getAlbumsAsync({includeSmartAlbums:true})` → "截屏/自拍/实况照片/全景"等智能相册归类，可靠；GIF 用启发式（video 且 duration≈0）；长图用宽高比>2.5。均为 best-effort，验收时明示。
- **EXIF 与文件大小（评审问题2的解）**：统一走 `getAssetInfoAsync(asset, {preserveJpegMetadata:true})` 导出临时 file:// → `expo-file-system` stat 取 fileSize、读字节 + 纯 JS `exif-parser` 取光圈/快门/ISO/焦距/设备。iCloud 未下载资产会触发系统下载：设超时，失败则降级为基础信息+"需要 iCloud"提示（对齐原 app 语义）。M1 末安排真机 spike 验证导出路径。
- **地址反查（评审问题3的解，我的裁决）**：`expo-location.reverseGeocodeAsync`（坐标 → Apple 系统地图服务）用于信息页地址文字；隐私声明修正为"照片内容不出设备；坐标仅送 Apple 系统反查"——与原 app 行为一致（其截图显示中文地址）。
- **取色渐变背景**：用 `expo-image` 内置 `ImageManipulator.mutateAsync`（勿用已废弃的 expo-image-manipulator）缩放 1×1 → base64 → 小段 PNG 解码得主色；双色取两处区域裁切。失败回退固定深色渐变。
- **confetti**：reanimated 粒子自绘（不用原素材，不引原生依赖）。
- **首启导入（评审问题5的解，默认策略）**：增量懒扫描——首次进入后台分批导入资产元数据并显示进度；`last_reviewed` 记录只存本机 SQLite，规模无关。
- **数据模型**（SQLite，镜像原 Core Data 语义）：
  - `media(id, local_identifier UNIQUE, cloud_identifier, media_type[photo|video|screenshot|selfie|live|gif|long], favorite, last_reviewed_at, last_locally_reviewed_at, width, height, creation_date)`
  - `deletion(id, local_identifier, media_type, deleted_at, file_size)`
  - `settings(key, value)`：每组数量、双击手势行为、时间格式、震动开关、HDR 开关
  - 分类判定：PHAsset mediaType + `mediaSubtypes`（截屏/自拍/全景…）+ 宽高比>2.5 判长图 + GIF 类型；实况用 `isLivePhoto` 标记（仅分类与徽章）。
- **随机算法**：未浏览（`last_reviewed_at IS NULL`）资产随机取 N；3 年回现规则简化为"永不自动回现，仅手动重置"（原行为：3 年后恢复——降级项，记入验收说明）。
- **删除语义**：上滑=入待删除队列（内存+SQLite pending 标记）；回收站勾选→`deleteAssetsAsync`（触发系统确认）；删除成功写 `deletion` 表并计算 fileSize 节省。撤回=移出队列。
- **导航**：tab（照片/视频/统计）+ modal（回收站、设置、回到那天、信息页）。

- 独立安装包：本期以 Expo Go 为运行形态。
